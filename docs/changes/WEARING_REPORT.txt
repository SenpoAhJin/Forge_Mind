KNOWN BUGS A–C (platforms reported separately)

A. Wig on the shoulder
WEB — RAN / OBSERVED: the red owned wig replaced the silver wig on the head.
Final framebuffer test found 124 red pixels at screen rows 62–71 in a 330-pixel
canvas; all are above the shoulder region. See wearing-evidence/red-wig-head.png
and web-results.json. Actual GLB probes put the male wig at y=1.773..1.915,
female y=1.760..1.915, above shoulder y=1.51989 / 1.52443 respectively.
The BEFORE probe already put the V2 wig on the head with identity root/mesh
transforms. The original shoulder patch was NOT reproduced in that probe, so
its precise origin/anchor cause is unconfirmed. No guessed head-offset fix was
introduced. Reachable wearing screens now use the measured V2 body-region path.
REAL PHONE — NOT RUN: no controllable real-phone connection was available.

B. Attire too small, misplaced, or failing to cover the body
WEB — RAN / OBSERVED: all five pieces generated on both actual V2 bodies;
front/side/back screenshots retained. Shoulder coverage was expanded to include
clavicles. A waist probe found 157/440 male and 168/445 female body triangles
uncovered between garment region definitions. The top now includes upper-thigh
regions within its existing hip boundary. Final waist coverage is 440/440 male
and 445/445 female, asserted by tools/wearing-geometry.mjs. Final top counts:
6664 male and 7090 female triangles. See wearing-coverage-before.json,
wearing-geometry-after.json and the six body/angle screenshots.
This is a simple body-derived colored-shape preview, as the task requires.
REAL PHONE — NOT RUN: coverage and interaction still need device observation.

C. Project Dashboard shows only a floor/black box
WEB — RAN / OBSERVED: the actual dashboard displayed its body and owned pieces,
with no unhandled page errors. See phoneframe-dashboard.png and
dashboard-body-and-owned-items.png. Source inspection found that the old costume
renderer defaulted to V1, then returned before mounting the body when the V2
contract was absent. The new costume path explicitly pairs V2 assets/contracts,
mounts the body independently, resolves asset URIs and clones the skeleton.
The original blank state was not recorded in a before-change browser session;
the after-change dashboard rendering was actually run and observed.
REAL PHONE — NOT RUN: Android export passed, but it is not a device render test.
